# Information Boundaries

Use this reference for placement and disclosure inside already established public, private, confidential, or other visibility boundaries. `../SKILL.md` owns the core contract. This file does not define privacy, security, organization, or project classification policy.

Use **information scope** for who may access information; keep it distinct from a rule's applicability scope.

## Confirm existing classification first

Identify source and destination information scopes, their authorities, and whether the operation crosses a boundary. Directory nesting, repository adjacency, similar names, and being on the same host do not prove identical visibility or ownership.

If applicable authority has not decided whether disclosure is allowed and the answer affects dependent work, stop disclosure/movement decisions rather than broadening access yourself.

## When classification appears wrong

This skill may identify that mandatory information cannot reach required consumers, public/private ownership conflicts with actual responsibility, or maintenance cost is distorted by current classification. Explain the evidence, affected behavior, and recommended classification, then request a decision. Continue to honor the current boundary until that decision exists.

## References and summaries across boundaries

When a broader-scope entry must point toward a narrower-scope component, retain only the responsibility, interface, input type, or navigation information that recipients are both allowed and required to know. Do not copy restricted settings, internal identifiers, or other sensitive detail merely to make a document self-contained.

If recipients cannot access a restricted reference, do not hide mandatory behavior only there. Re-place the minimum disclosable mandatory rule rather than creating a hidden dependency.

## Moving and synchronizing information

Before moving information from a narrower to a broader scope, reconfirm disclosure authorization, derived copies, and dependents. After movement, update links and ensure the old location does not retain a competing current version.

If redaction is required, preserve enough structure to support the judgment and mark the redaction. Never replace unavailable evidence with invented values.

Information-boundary changes alter the dependency graph; propagate them through [change-impact.md](change-impact.md) when triggered.
